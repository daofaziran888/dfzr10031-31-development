# 数据分析实验与数据应用服务平台

面向指标口径管理、分析实验设计、OLAP查询、数据看板构建与数据API发布的数据应用平台。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 模型评估结果数据集

同一评估批次（`model_eval_batch`）下挂一份评估集样本（`model_eval_sample`），
样本编号、真实分类与样本分组属于评估集；每个模型版本按样本逐条汇入结果
（`model_eval_result`），预测分类留空即弃答，弃答仍要登记。

- 汇入：`POST /api/model_eval/import`，要求覆盖评估集全部样本，真实分类必须与评估集一致。
- 指标：命中率 = 正确 / 已作答；覆盖率 = 已作答 / 评估集样本；正确响应占比 = 正确 / 评估集样本。
- 人工复核：`GET /api/model_eval/review-queue` 单列弃答、少数类别弃答与金标人工复核样本，
  `POST /api/model_eval/results/{id}/review` 回写复核结论。
- 比较口径：主比较为共同覆盖准确率（只取两版本都作答的样本，共同覆盖为 0 时不给出差值）；
  辅助比较为全评估集正确响应占比（弃答计入分母、不计为正确）。差值方向为版本 A - 版本 B。
- 留存与回看：`POST /api/model_eval/compare` 留存比较结果（含评估批次、分母与样本覆盖），
  `GET /api/model_eval/comparisons/{id}` 在任何版本切换后重新打开并核对。

看板页（`/dashboard`）下方嵌入「分组评估视图」，逐组列出分母、共同覆盖样本数、主比较差值、
比较依据、是否可直接比较与预测缺口。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。
